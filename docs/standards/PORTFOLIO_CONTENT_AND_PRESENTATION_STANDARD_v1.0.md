**Status:** Approved\

## Purpose

This standard defines how every project in the portfolio is presented to
ensure consistency, technical depth, SEO readiness, bilingual quality,
and professional storytelling.

## Portfolio Philosophy

The portfolio is evidence of engineering capability---not simply a
showcase of code.

Every project should answer: - What was built? - Why was it built this
way? - What engineering challenges were solved? - Why should someone
trust me to build something similar?

Reading model: - 10 seconds: Hero - 1 minute: Summary + Engineering
Highlights - 5 minutes: Full case study

## Required Metadata

-   Title
-   Subtitle
-   Status
-   Project Type
-   Industry
-   Timeline
-   Role
-   Team Size
-   Repository Visibility
-   Technology Stack
-   Categories

## Repository Policy

-   Public: Show GitHub link.
-   Private: Show "Repository: Private".
-   NDA: Show "Source code unavailable due to client confidentiality."

## Hero

Include: - Hero image - Status - 90--140 word summary - Technology
badges - Links

## Engineering Highlights

Include 5--8 concise technical achievements.

## Case Study Order

1.  Overview
2.  Problem
3.  Goals
4.  Architecture
5.  Technical Decisions
6.  Challenges
7.  Security
8.  Scalability
9.  Results
10. Lessons Learned
11. Future Improvements

## Writing Standard

Explain *why* before *how*. Use professional, technical language. Avoid
marketing terms.

## AI

AI may assist with drafting, localization and SEO, but every output
requires human approval before publication.

## Localization

English is the source language. French must be written as native
technical content, not translated literally.

## SEO

Every project requires: - Meta title - Meta description - OpenGraph -
Canonical URL - Structured data

## Accessibility

Maintain semantic HTML, keyboard accessibility, focus states, and
appropriate ARIA.

## Performance

Optimize images, preserve Core Web Vitals, and use ISR appropriately.

## Publication Workflow

Draft → AI Draft (optional) → Human Review → Technical Review →
Localization Review → SEO Review → Published

## Definition of Done

A project is complete only after: - Metadata - Hero - Engineering
Highlights - Case Study - Architecture Diagram - Screenshots - SEO -
Localization - Accessibility - Performance - Final Proofreading

## Quality Gate

Every project passes: - Engineering Review - Presentation Review -
Recruiter Review - Portfolio Consistency Review
